## 1. Evidence Integrity & Architectural Guardrails

According to the evaluation criteria, architectural guardrails are prioritized over prompt-based instructions. KuroTech Yomi enforces evidence integrity strictly at the code architecture level, ensuring zero risk of evidence spoliation.

- **VETO Interception (Hardcoded Logic):** The system does not rely on LLM prompts to protect critical OS processes. When the agent attempts to target a protected process, the air-gapped `HARNESS` automatically intercepts the action. The execution logs cryptographically prove this boundary enforcement: an attempt to modify PID 1 resulted in a deterministic `VETO_ENGAGED` event stating "Target PID 1 is classified as a protected critical OS process or access was denied".
- **Context Window Protection (Vault Shield):** To prevent LLM context window overflow and hallucination triggers when processing massive memory dumps (e.g., Volatility `malfind` outputs), Yomi utilizes an architectural Vault Shield that safely truncates outputs to exactly 100 kilobytes before they reach the LLM context.

## 2. Self-Correction & Hallucination Control

Yomi operates on a Persistent Learning Loop architecture. The system identifies degraded confidence or tool failures and autonomously re-sequences its approach through iterative loops.

- **Graceful Degradation via Max-Iterations Cap:** A known failure mode of multi-agent frameworks is infinite conversational spirals. Yomi mitigates this architecturally. As proven in the `yomi_chain_of_custody.jsonl` ledger, the `ROUTER` executes up to three structured triage iterations (`TRIAGE_ITERATION 1` to `3`). If verification criteria are unmet, the system forcefully terminates the LLM loop, logs a `MAX_ITERATIONS_REACHED` event, and gracefully degrades to a deterministic `Shadow Net fallback`.

## 3. Documented Failure Modes (Honesty Declaration)

In alignment with the SANS mandate that "Honesty valued over perfection," the following false positives, missed artifacts, and system limitations were identified during testing. Documenting these flaws is a core aspect of our rigorous accuracy evaluation.

- **Missed Artifacts in Output (Dossier Generation Bias):** The automated `WEAVER` agent generates human-readable PDF and TXT dossiers sealed with HMAC-SHA256 signatures. However, a known limitation exists in our current regex compilation logic. The final generated `YOMI_DOSSIER` heavily biases towards logging high-frequency, concurrent `SWARM` ("Completed resilient concurrent agent sweep") and `MITRE_MAPPER` ("Mapped 2 unique tactics") actions. Consequently, high-level cognitive insights and psychological profiles generated by the `MINDREADER` agent are visibly omitted from the human-readable reports.
- **Audit Trail Preservation:** The omission mentioned above is a parsing constraint, not an AI hallucination. The immutable JSONL ledger successfully captures and preserves the missing cognitive intelligence, including the creation of dynamic APT signatures (e.g., `CVE-2026-YOMI4209`) and exact token usage metrics.
- **Tool Failure Handling:** When raw disk artifact hunters (TSK/Plaso) attempt to parse unsupported partitions, the system occasionally produces spatial errors. Rather than crashing, the agent successfully parses the explicit failure, logs the error cleanly, and re-routes its investigative path.
